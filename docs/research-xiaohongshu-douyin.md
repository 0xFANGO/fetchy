## 小红书

### 上游实现所表明的机制（源码事实）

yt-dlp 的小红书适配器读取页面 `window.__INITIAL_STATE__`，按笔记 ID 找到 `note.noteDetailMap[id].note`，从 `video.media.stream` 收集媒体条目。每个条目的 `masterUrl` 与 `backupUrls` 都可能成为可下载地址，同时保留分辨率、编解码器、码率、大小、时长等信息。适配器还会在存在 `originVideoKey` 时尝试原始视频地址；这个分支只是可选候选，不能保证每条笔记都提供原视频。[上游源码](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/xiaohongshu.py)

由此形成的设计建议：完整保留输入中的 `xsec_token` 等访问参数到解析阶段；显示及日志中隐藏 token。先确认目标笔记 ID，再选择其媒体，避免把推荐视频或封面识别成目标。多个 CDN URL 可能只是同一清晰度的镜像，应按清晰度分组，再做镜像回退。

### 样例观察

- `XD-OBS-01`：`yt-dlp 2026.06.29.234344`，显式 `--ignore-config --skip-download --no-playlist`，网络超时 15 秒、重试 0。匿名解析退出码为 0。
- 标题：`最有节目效果一幕tim连麦被强制下麦`；ID 与用户输入一致；时长 146.7 秒。
- 三个候选均为 720 × 1404、30 fps、H.264 视频与 AAC 音频、MP4，元数据大小均为 19,875,696 字节，质量标记为 HD。这是三条同规格镜像，不是三档清晰度。
- 主候选域名为 `sns-video-v4.xhscdn.com`，备用域名为 `sns-bak-v1.xhscdn.com`、`sns-bak-v6.xhscdn.com`。发现的媒体 URL 查询字段包括 `b/csig/oi/sign/t/trid`；本报告不保存这些字段的值。
- `XD-OBS-02`：对主候选发出 `Range: bytes=0-65535` 请求，得到 HTTP 206、`Content-Type: video/mp4`、`Content-Range: bytes 0-65535/19875696`。读取 65,536 字节，文件头存在 MP4 `ftyp` 标记。

这证明本次会话中解析结果至少有一个可读取的 MP4 资源。它不等价于完整文件可播放验证。没有运行去水印处理，也不能仅凭 URL 命名或“原始”字段宣称视频没有水印。虽然 URL 带签名字段，本次没有测量其过期时间，不应写死缓存 TTL。

## 抖音

### 上游实现所表明的机制（源码事实）

当前上游 `DouyinIE` 直接识别 `/video/<数字 ID>`，使用视频 ID 请求网页详情接口 `/aweme/v1/web/aweme/detail/`，再提取详情中的媒体候选。候选包括 `play_addr`、`download_addr`、不同编码地址和 `bit_rate` 里的播放地址；每个地址对象又可能包含多个镜像。实现读取 `has_watermark` 标记并调整下载候选偏好，不能因此认为所有 `play_addr` 都无水印。详情缺失时，上游给出 fresh cookies 错误；这是一种宽泛错误，不能据此证明视频必须登录、已删除或验证码是唯一原因。[上游源码](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/tiktok.py)

### 样例观察

- `XD-OBS-03`：以用户原始地址 `https://www.douyin.com/jingxuan?modal_id=7695202760953793827` 调用相同匿名探测参数，退出码 1，错误为 `Unsupported URL`。
- `XD-OBS-04`：将 `modal_id` 提取为字符串 ID，归一为 `https://www.douyin.com/video/7695202760953793827` 后重试。进入 `Douyin` 提取器，退出码 1，错误为 `Fresh cookies (not necessarily logged in) are needed`。
- 两次探测均未下载视频；没有为解决该错误导出浏览器 Cookie。这里不能得出“抖音无法下载”的全平台结论，只能得出“给定样例的当前匿名提取路径未成功”。

优先把此类结果映射成 `SESSION_REQUIRED` 或 `ACCESS_BLOCKED`，保留恢复提示“在可正常播放该视频的浏览器会话中重新解析”；不要无界重试，也不要把详情响应失败误报成“视频不存在”。用户会话补充之后应重新验证，仍然可能失败。上游已有携带 Cookie 后仍然报同类错误的报告，说明 Cookie 不应被当成成功保证。[上游问题记录](https://github.com/yt-dlp/yt-dlp/issues/12669)

## 对统一接口的要求建议

1. 平台识别与视频 ID 抽取在网络下载之前执行。抖音 `modal_id` 是当前样例必需支持的入口；长数字 ID 始终作为字符串，避免 JavaScript 数字精度损失。
2. 小红书同时接受 `/explore/<id>` 与 `/discovery/item/<id>`。不要先删掉全部查询参数再解析。抖音、小红书短链接需要受控跟随 HTTP 跳转后重新识别，未知跳转目标应拒绝；初轮没有短链样例，后续抖音短链的真实验收见末节，小红书短链仍待验收。
3. 解析结果包含候选规格及镜像，内部下载计划携带临时 URL 和必需请求头；对外日志与历史记录避免保存签名 URL、token 或 Cookie。
4. 输出 `watermark: unknown | yes | no`，缺少可靠证据时使用 `unknown`，不要承诺“全平台无水印”。页面提供的图文笔记不能作为视频下载成功，单独返回内容类型不支持。
5. 成功标准分三级记录：元数据解析成功、媒体字节可获取、完整文件校验通过。只有最后一级才能登记样例下载成功。
6. 下载失败应区分输入不支持、会话/访问受阻、无视频候选、媒体 URL 失效、网络中断和文件校验失败。可用镜像按顺序有界回退；403 等情况只允许有界重新解析，避免反复复用已失效地址。

这些是依据本轮调查形成的设计要求，完整落实情况以主实现和验收记录为准。

## 浏览器状态补充观察

以下两项由主调查者通过 Ego 浏览器观察后回传；它们不是 REA Evidence ID，也不是本子调查重新执行的浏览器操作。后续主调查应保存其完整脱敏证据。

- `EGO-XHS-1`：匹配同一笔记 ID 的 `note.video.media.stream` 包含 EF4 与 EF5 两组。EF4 中为 720 × 1404、19,875,696 字节；EF5 中另有 720 × 1404、10,946,185 字节，以及 984 × 1920、10,167,052 字节。此前匿名 yt-dlp 返回的 720P 镜像并未覆盖此浏览器会话可见的全部候选。不能只读取 H.264 组，也不能把匿名 HTML 的结果当作该视频的最高质量上限。
- `EGO-DY-1`：`RENDER_DATA` 是 URI 编码的 JSON，其 `app.videoDetail.awemeId` 匹配 `7695202760953793827`。详情中的 `video.duration` 为 2,082,067 毫秒，视频尺寸为 1080 × 1920；`playAddr` 是包含 `src` 的数组，`bitRateList` 约 21 条，带宽、大小、编码和镜像信息分布在各候选中。部分条目有 `audioFileId/indexRange`，属于需要额外处理的音视频分离候选。

补充实现 `src/page-extract.mjs` 只读取匹配 ID 的这两种页面结构，并导出可独立序列化执行的 `extractPageMedia`。它收集小红书所有编码组；抖音首版排除带 `audioFileId` 的条目，仅在没有码率列表时使用顶层 `playAddr`。输出中的 `hasAudio/hasVideo` 是候选分类，必须在实际下载后用 ffprobe 验证。候选被提取出来不代表下载成功。

主调查后续确认小红书 SSR 有时给出 HTTP 地址，但播放器实际请求的是 HTTPS。因此页面提取器对已经通过 `*.xhscdn.com` 域名检查的 HTTP URL，仅替换协议为 HTTPS，保留其余签名参数原样。抖音仍拒绝 HTTP；输出仅包含 HTTPS。小红书允许 `*.xhscdn.com`，抖音暂允许 `*.douyinvod.com`。这是本次实现的明确边界，不代表平台只使用这些 CDN。

字段语义也随页面环境有差异：主调查浏览器数据的 `videoCodec` 使用 EF4/EF5 标签，而本子调查再次读取匿名 SSR 时，同规格条目的流组与 `videoCodec` 均为 `h264`、`audioCodec` 为 `aac`。实现兼容明确的编码名；本次 EF4 文件已由 ffprobe 和完整解码确认是 H.264。EF5 等不透明标签保持未知，下载结果以 ffprobe 实际编码为准。上游 yt-dlp 和旧下载 skill 都直接透传 codec 字段，没有提供 EF 标签映射定义。抖音的 `videoFormat=mp4` 是容器，不能作为视频 codec；实现仅通过显式 `isH265` 布尔值或 0/1 确认 H.264/H.265，缺失时保持未知。

页面提取器 10 项单元验证覆盖身份校验、两组小红书候选、抖音分离流过滤、镜像归组、域名限制、HTTP 升级不改签名、codec 字段解释和脱离模块闭包的页面执行。
