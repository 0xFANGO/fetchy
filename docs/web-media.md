# Web downloads and offline posts

Use `node bin/fetchy.mjs info '<URL>'` to inspect public media and `get` to save it. A media result has a validated local path, a library task ID and an offline page. Pass `--output <directory>` for an additional file named after the work. The original `resolve` and `download` commands retain their existing behavior.

| Input                       | What Fetchy reads                                                                          | Verification                                                                                     |
| --------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Direct MP4 or WebM          | HTTP response and the actual container header                                              | A generated direct MP4 opened and decoded completely                                             |
| HTML video                  | A video element, its source elements, or declared Open Graph video                         | A page with an unavailable first candidate and a working MP4 produced the same H.264/AAC streams |
| HLS video on demand         | Finite playlist, selected variant, available audio rendition, and local copies of segments | A declared two-segment stream decoded completely                                                 |
| Static DASH                 | A single period, audio/video representations and their initialization and media segments   | A declared two-track presentation produced a complete MP4                                        |
| Media loaded after playback | A selected stream in the browser or a unique supported same-origin file in Fetchy Browser  | A controlled WebKit player exposing a blob URL saved an authenticated progressive file           |
| Readable article            | One semantic article, including headings, paragraphs, links and accessible media           | Local HTML preserves text and relative paths to archived attachments                             |

The generated direct, HTML, HLS and DASH fixtures use two seconds of 160×90 H.264 and AAC. The integration test decodes the complete output with FFmpeg and checks duration, video and audio. Run `node --test test/generic-media.test.mjs` to repeat these checks. The opt-in macOS WebKit test is documented in the [desktop guide](desktop.md).

Public-web fetches allow HTTP and HTTPS. Fetchy checks each destination and redirect before connecting. Networks that map public hostnames into reserved address space can prevent a direct fetch. Use the current-page capture for media the browser can read. A loopback fixture needs `--allow-local` and the same explicit loopback origin for its segments. Encrypted, live, byte-range and multi-period manifests are outside the current generic decoder. On a page with a timed-out login, use `browse` on the original URL, sign in, then repeat `get`.

A collection reports how many items were visible and whether it reached the site's declared total or an explicit end. A missing body, inaccessible attachment, preview image or stalled page stays visible in the result. A separate check used two disjoint slices of the signed-in collection feed. Selecting one ID from each yielded exactly those two. Selecting both visible slices kept all their IDs and reported further history as unread. On an owner-authorized Xiaohongshu account, the capture function found the named albums, checked their visible members, and retained count mismatches. An independently reopened final member matched the displayed note ID. For a three-image note the offline text matched the original and each file matched the corresponding browser-readable bytes. All three images decoded in an offline browser with only local file requests. The site did not expose a save timestamp for the checked album member.
