# 实现边界与输出说明

本文承接 README 中原有的"实现边界"与"通用方法"细节，供需要了解具体行为的用户和贡献者查阅。README 只保留面向首次使用者的摘要。

## 范围

- 只处理单个已完成的视频；合集、直播、图文、DRM、精确裁切不在首版。
- 分享链接中的 `t=4538s` 只记录播放定位，默认仍下载整片；首版没有自动裁切。
- 选择的是本次实际解析到的规格，不能承诺"全站最高画质"或"无水印"。浏览器引擎同规格偏好 H.264 兼容性，不按跨编码码率硬排画质；yt-dlp 下载先选择兼容编码组，再在组内使用自身格式排序。
- 小红书不同加载状态可返回不同编码/清晰度；抖音浏览器首版排除有独立音轨标记的候选。

## 输出格式

- yt-dlp 引擎（默认用于 YouTube/B站）最终交付 MP4，校验 H.264、yuv420p 和 AAC 音频。优先获取原生兼容流；缺少时下载可用源并转码，不只是修改后缀。原生兼容流的最高规格可能低于其他编码，实际规格以结果为准。
- 必要转码使用 FFmpeg，可能增加耗时和文件大小，也可能损失画质；下载结果的 `conversion` 用 `copy` / `remux` / `transcode` 区分直接使用、无损重封装与重新编码。
- 浏览器引擎的小红书/抖音保留源 MP4 编码，例如 HEVC，不承诺 H.264 输出。
- 默认用 ffprobe 检查视频、预期音频和时长；`validation.fullDecode: false` 明确表示未逐帧完整解码。
- `--max-height` 是实际帧高度，例如 1080×1920 竖屏高度为 1920。

## 文件命名

成功文件直接保存到所选输出目录，文件名使用实际视频标题，例如 `中文视频标题.mp4`，不保留外层任务文件夹。标题中的路径/控制字符会清理，过长标题会截短，缺少可用标题时以内容 ID 等信息兜底；同目录重名自动加序号，例如 `中文视频标题 (2).mp4`，不覆盖已有文件。下载和校验使用独立临时工作目录，结束后清理。扩展、CLI 和 Node API 使用相同规则。失败不留下伪装成成片的文件。

## 引擎与会话

- 浏览器引擎只处理小红书/抖音，且只在调用方传入 `pageMedia` 时启用：扩展把 `src/page-extract.mjs` 注入你浏览器里的视频页，取回目标视频的媒体候选后交给本地组件下载。核心会把传入的媒体信息重新与链接身份、CDN 域名校验一遍。
- 命令行和不带 `pageMedia` 的 API 调用对全部平台使用 yt-dlp 的匿名解析；小红书和抖音在这条路径上可能需要 Cookie 或拿到更少的规格。
- 不导出 Cookie。遇到登录/验证提示，在浏览器里的视频页完成后重试即可；扩展后台打开的标签页同样使用当前浏览器的登录态。
- YouTube 在 HTTPS 传输遇到网络错误时会有限尝试 HLS；结果中 `fallback: 'https_failed_retry_hls'`。
- `cookiesFile` / `--cookies-file` 仅用于显式指定的 yt-dlp 引擎，使用临时私有副本，不回写原文件。浏览器引擎可设 `maxBytes`（默认 4 GiB）。

## 隐私

签名媒体地址只用于当前任务。Cookie、访问 token 和原始页面状态不写入公开日志/版本库。扩展的持久化任务记录剔除访问参数与临时凭据；原始访问输入只在本机会话内存中保留，浏览器完全重启后可能需要重新粘贴原始链接。首版不提供断点续传。

## 测试覆盖

`npm test` 覆盖核心契约、真实 FFmpeg 的 MP4 重封装/转码、弹窗/后台竞态、Native Messaging 分帧、任务去重、取消确认、目录冻结、结果校验及真实 host/daemon 断连恢复。离线测试不访问真实平台、不启动真实浏览器。真实平台的人工验证分别记录在[核心实测记录](validation.md)和[扩展验证记录](extension-validation.md)，其中核心成功不等同于插件四平台全部通过。
