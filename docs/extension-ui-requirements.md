# 浏览器扩展界面与交互规范

本文定义 Fetchy 浏览器扩展的界面结构、交互状态、任务生命周期、安全边界与验收标准。[下载核心契约](requirements.md)继续约束 URL 身份、媒体解析、输出格式、错误与文件校验；本地组件协议与注册细节见 [本地组件说明](../native/README.md)；安装与排障见 [扩展安装与使用](extension-install.md)；真实插件验证记录见 [扩展验证记录](extension-validation.md)。

## 1. 目标与范围

完成「识别视频 → 确认封面和标题 → 下载到指定目录 → 找到文件」的单视频下载流程。用户点击浏览器工具栏中的插件图标，打开弹窗；界面简洁，以可靠完成下载为优先。

### 核心能力

- 工具栏图标与主弹窗：自动识别当前活动标签页的视频链接。
- 视频卡片：封面、标题、平台、已知时长和下载按钮。
- 手动输入：粘贴或输入一个视频链接或分享文案，识别成功后复用相同卡片。
- 单个下载任务：阶段反馈、取消、失败重试、成功后在 Finder 中显示。
- 目录选择：在弹窗底部直接更改保存目录，选中后自动保存并持续生效。
- 弹窗关闭后下载继续；重新打开能够恢复任务状态。
- 连接本地 Native Messaging 组件，并提供安装指引与连接失败反馈。

支持平台限定为 YouTube、B站、小红书和抖音，内容限定为单个已完成的视频。“支持平台”不承诺该平台任意视频都能下载。

### 实现路线与平台边界

采用 **浏览器扩展（Manifest V3）+ Native Messaging 本地组件**，复用 Node、yt-dlp、FFmpeg/ffprobe 核心。Chrome `chrome.downloads` API 的自动目标路径限于默认下载目录内的相对路径，因此通过本地组件调用系统目录选择器并校验任意可写目录。参考：[Downloads API](https://developer.chrome.com/docs/extensions/reference/api/downloads#type-DownloadOptions)、[Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)。

当前本地组件安装与真实验证面向 **macOS + Chromium Manifest V3**（已在 Ego Lite 实测，Chrome 注册路径已提供但尚未端到端实测）。

### 不在范围内

批量或队列、完整下载历史、暂停与断点续传、清晰度和格式选择、账号系统、云同步、右键菜单、快捷键配置、主题切换。合集、直播、图文、字幕/弹幕、裁切、去水印和 DRM 处理沿用核心范围限制。

## 2. 界面结构

弹窗宽约 360px，高度随内容变化并受浏览器可用空间约束，超出时内部滚动。主视图只突出当前任务的主要操作，底部提供当前保存目录与「更改」入口；不展示引擎路径、编码器参数、调试编号等实现细节。

主界面示意（排版参考，不限定像素细节）：

```text
Fetchy

[ 视频封面 ]  视频标题，最多两行
              平台 · 时长（已知时）

[          下载视频          ]
更换链接
保存到：~/Downloads/Fetchy               更改 >
```

未识别到视频时，用以下内容替换视频卡片和下载按钮：

```text
当前页面未识别到支持的视频
[ 粘贴视频链接               ]
支持 YouTube、B站、小红书、抖音
```

### 视频卡片规则

- 封面应属于识别出的目标视频；不得使用推荐视频或广告图片凑数。
- 无封面或加载失败时使用统一占位图，不阻断已经就绪的视频下载。
- 标题最多显示两行并截断，能够查看完整标题；未知时使用“未命名视频”等明确兜底。
- 平台和时长作为次要信息，未知时长不显示，不能填入虚构数值。
- 一个状态只有一个主要操作；“更换链接”、取消和返回等使用次要样式。
- 输入框、图标按钮和状态提示具备可访问名称、键盘焦点和可读反馈；错误不能只用颜色表达。

## 3. 自动识别与手动输入

### 打开弹窗

1. 先恢复正在执行的任务；如有任务，优先展示其进度，不重新解析其他页面覆盖任务。
2. 有尚未查看的任务结果时先展示结果，用户可返回识别当前页面。仅保留当前任务及最近结果，不做历史列表。
3. 没有上述任务状态时，读取当前窗口活动标签页的 URL。新的自动识别不得覆盖用户正在编辑的手动链接或尚未完成的手动识别。
4. 对支持的视频链接调用解析，显示“正在识别视频…”。解析得到目标信息和可用媒体候选后展示视频卡片，允许点击下载；这不表示媒体传输已验证成功。
5. 普通网页、平台首页、搜索页、浏览器内部页或无法读取 URL 的页面，展示手动输入，不将正常空状态渲染成系统故障。
6. 对明确的视频链接解析失败时，展示错误原因及重试/修改链接入口，不能把网络、登录或本地组件故障统一说成“当前页面不是视频”。

当前页面发生导航或视频 ID 改变时，应使旧的自动识别结果失效。已经开始的下载继续绑定原目标，不随标签页切换而改变。URL 不提供明确目标的推荐流不猜测当前播放项，可回退到输入具体分享链接。

### 手动输入

- 粘贴有效输入后自动识别；手动键入停止后短暂防抖识别，回车可显式触发或重试。
- 支持一个链接或含单个链接的分享文案；多个不明确链接要求用户只保留一个，不做批量下载。
- 输入为空时不请求解析；格式或平台不支持时就地提示并保留输入。
- 输入变化时取消或忽略旧请求，只有最新输入对应的结果能够更新卡片。不得发生输入 B 后显示或下载 A 的情况。
- 成功后复用自动识别的视频卡片，用户点击“下载视频”才开始下载，不因粘贴或解析成功自动下载。
- 卡片保留“更换链接”入口。弹窗关闭再打开时保留本次手动输入/识别上下文；用户明确返回当前页面识别时再清除手动优先状态。

URL 归一化继续保留 B站分 P、小红书必要访问参数、抖音字符串视频 ID 和分享短链目标；YouTube 时间戳只表示播放定位，默认下载整片。

## 4. 状态与下载生命周期

| 状态     | 展示                         | 可执行操作与行为                               |
| -------- | ---------------------------- | ---------------------------------------------- |
| 等待输入 | 输入框与支持平台提示         | 输入或粘贴链接                                 |
| 识别中   | “正在识别视频…”与加载反馈    | 可修改输入；旧响应不能覆盖新结果               |
| 已识别   | 视频卡片、保存目录           | 下载视频、更换链接、更改目录                   |
| 下载中   | 视频卡片、当前阶段或真实进度 | 取消；禁用重复下载与目录更改，不创建第二个任务 |
| 取消中   | “正在取消…”                  | 等待执行端确认停止并清理，不立刻宣称取消成功   |
| 已取消   | “已取消下载”                 | 可重新下载或更换链接                           |
| 已完成   | “已保存”与实际保存位置       | 在文件夹中显示；返回当前页面或更换链接         |
| 失败     | 简明原因，保留原目标/输入    | 重试或修改链接                                 |

本地组件未安装、不可连接或缺依赖时，在主视图显示可操作的说明、安装指引入口与重试按钮，保留用户输入；不将“请求已发送”当作任务已开始。

### 进度与完成判断

- 对接阶段：`resolving` → 正在解析视频，`downloading` → 正在下载，`postprocessing` → 正在处理音视频，`validating` → 正在校验文件，`retrying` → 正在重试，`refreshing` → 文件校验失败，正在刷新视频地址并自动重试。
- 有可靠的字节数与总量才显示百分比，否则只显示阶段和不定进度。不得伪造百分比或将下载字节完成等同于合并/校验完成。
- 只有核心成功返回实际文件路径和有效校验结果后，才将任务标记完成。解析成功、HTTP 200、进程退出或消息投递成功都不足以显示“已保存”。
- “在文件夹中显示”定位本次实际输出文件，不能只打开配置的根目录。文件已被移走或删除时给出明确提示。
- 下载与校验使用独立临时工作目录；成片以清理后的标题直接保存到所选输出目录，同名自动加序号，不覆盖用户文件。任务结束后清理临时工作目录，界面显示最终文件的实际位置。

### 关闭、重开与重试

- Popup 只是任务的视图，不能持有下载执行的唯一生命周期。关闭弹窗或切换标签页，都不得取消下载。
- 后台与本地组件管理稳定任务 ID、当前目标、阶段和结果；启动请求要防重复。重新打开弹窗通过状态查询恢复，不重新发起下载。
- 必须处理扩展后台 service worker 重建、Native Messaging 连接中断和恢复。弹窗端口断开不得直接结束正在执行的任务；通信断开时不得虚报完成或自动重复启动。
- 浏览器完全退出、电脑重启、进程崩溃后不提供断点续传；再次启动如发现无法恢复的任务，应显示已中断并允许重新下载，不能永久显示下载中。
- 取消调用核心可取消能力，并清理本次未完成文件。小红书和抖音下载首次出现 `output_invalid` 时允许后台临时页刷新媒体并自动重试一次；手动失败重试使用原始目标重新解析，不复用可能过期的媒体签名 URL。

浏览器弹窗点击外部区域会自动关闭，因此关闭后的任务持续与重开恢复是必须验收的能力。参考：[Chrome Popup 文档](https://developer.chrome.com/docs/extensions/develop/ui/add-popup)。

## 5. 下载目录行为

- 默认目录为操作系统下载目录下的 `Fetchy` 文件夹（`~/Downloads/Fetchy`），不使用启动进程的相对工作目录作为默认位置。
- 主弹窗底部展示当前目录并提供「更改」按钮，通过本地组件调用系统目录选择器；选中后校验并自动保存，重启后仍保留，取消选择不改变已有设置。
- 保存前校验目录可用、可写；默认目录可按需创建，失败时给出具体反馈，不静默改存其他位置。下载开始时再次检查目录，避免已删除或权限已变化的路径被误用。
- 下载开始时固定本次输出目录；显示任务期间禁用目录更改，避免与当前任务的固定目录混淆。
- 系统目录选择器可能导致弹窗收起，待保存的选择结果由本地 daemon 保留（`pendingDirectory`），重开弹窗后不会丢失并能完成保存或显示最新目录。
- 长路径在界面中省略显示（如折叠主目录为 `~`）并通过提示保留完整路径；主界面的保存目录与本地执行配置保持一致。

## 6. 页面读取与桥接安全边界

- **小红书/抖音会话路径**：扩展直接把 `src/page-extract.mjs` 注入用户当前浏览器中已打开的目标视频页（无可用页、短链展开或校验失败自动刷新时打开不激活的临时后台标签页并读完即关），仅取回目标视频的标题、封面和媒体候选，经 `pageMedia` 交给本地组件，由核心重新校验内容身份和 CDN 域名后下载。
- **不导出凭据**：不导出全浏览器 Cookie、localStorage，也不绕过验证码；需要登录或验证时提示用户在当前浏览器完成后重试。
- **最小权限与脱敏**：扩展仅申请完成上述流程所需的权限；页面标题和错误文本按普通文本渲染；原始分享输入、访问参数、token 和签名媒体 URL 不写入持久任务记录或公开日志。本地桥接协议、来源校验与持久化脱敏详见 [本地组件说明](../native/README.md) 和 [SECURITY.md](../SECURITY.md)。

## 7. 错误提示与恢复

| 情况                           | 用户可理解的提示方向                       | 下一步                                   |
| ------------------------------ | ------------------------------------------ | ---------------------------------------- |
| 链接格式无效或多个目标         | “请输入一个有效的视频链接”                 | 保留输入并修改                           |
| 平台不支持                     | “暂不支持此网站”，列出四个平台             | 更换链接                                 |
| 图文、直播或无可用视频候选     | 依据实际结果提示当前内容不支持或无可用视频 | 更换链接或重试；不假装已识别到可下载视频 |
| 登录、验证或会话条件不足       | 提示在当前浏览器完成登录或验证             | 用户完成处理后重试                       |
| 网络错误或超时                 | “连接失败”或“识别/下载超时”                | 有界重试，保留输入                       |
| 本地组件/依赖缺失              | 说明缺少的组件及安装指引入口               | 安装或修复后重试                         |
| 目录不可写或磁盘不足           | 说明保存失败的原因                         | 更改目录或释放空间后重试                 |
| 身份不匹配、媒体或文件校验失败 | “无法确认目标视频”或“下载文件校验失败”     | 拒绝完成，允许重新解析/下载              |
| 用户取消                       | “已取消下载”                               | 可重新下载，不作为系统故障展示           |

错误分类沿用核心契约，不从所有 403 推断必须登录、内容删除或地区限制。未分类错误使用简洁说明和重试入口，避免直接显示包含凭据的原始日志。

## 8. 验收标准

实际已完成的自动化与真实验收证据见 [扩展验证记录](extension-validation.md)；下表为验收基线清单。

| 编号 | 场景                                       | 通过标准                                                              |
| ---- | ------------------------------------------ | --------------------------------------------------------------------- |
| A01  | 支持平台的具体视频页打开弹窗               | 有识别反馈；成功后卡片与当前目标一致，下载按钮可用                    |
| A02  | 普通网页、平台首页或浏览器内部页           | 展示输入框，可粘贴链接继续流程，不无限加载                            |
| A03  | 手动输入/粘贴有效链接                      | 自动识别，回车可重试；展示卡片后由点击下载才启动任务                  |
| A04  | 自动结果更换链接、快速输入 A 再改 B        | 可手动切换；A 的迟到响应不能覆盖 B，下载与所见目标一致                |
| A05  | 标签页导航、分 P 或视频 ID 变化            | 旧自动结果失效；已开始任务仍下载原目标                                |
| A06  | 无封面、图片加载失败、长标题、未知时长     | 占位和排版正常，主要操作可用，未知信息不虚构                          |
| A07  | 短链、分享文案和带参数链接                 | 复用核心规则，保留目标、分 P、必要访问参数；YouTube 默认下载整片      |
| A08  | 连点下载、关闭后立即重开                   | 同一启动操作只产生一个任务；不并行启动第二个下载                      |
| A09  | 下载中关闭弹窗、切换页面                   | 文件下载继续；重开恢复同一任务与当前阶段                              |
| A10  | 扩展后台重建或桥接暂时断开                 | 可重连查询同一任务；不虚报成功、不重复启动；不可恢复时明确显示中断    |
| A11  | 下载、处理、校验、自动刷新各阶段           | 阶段文字符合实际；无可靠总量不显示百分比；未校验成功不显示完成        |
| A12  | 下载成功                                   | 文件存在且核心校验通过；界面显示实际位置，定位按钮选中/显示实际文件   |
| A13  | 用户取消、网络失败、校验失败               | 终态准确，保留可重试目标，未完成文件清理，不覆盖用户原文件            |
| A14  | 首次默认目录与自选目录                     | 默认使用系统下载目录下的 Fetchy；自选可写目录实际生效，重启后设置保留 |
| A15  | 目录选择器导致弹窗关闭、取消选择、目录失效 | 重开不丢选择结果；取消不改设置；失效显示错误，不静默改存其他目录      |
| A16  | 任务目录冻结                               | 下载开始时固定原目录；任务显示期间禁止更改，下次任务使用新目录        |
| A17  | 缺本地组件/依赖、页面未就绪、需登录/验证   | 可理解、可恢复的错误指引；不能把任意故障归为无视频                    |
| A18  | 键盘操作和异常内容                         | 能聚焦输入/按钮、回车识别、读取状态；标题按文本显示，日志不泄露凭据   |

验证覆盖两层：用离线/模拟测试验证状态机、竞态和重开恢复；在声明支持的环境中，通过真实插件连接本地组件验证四个平台的识别、下载、校验及弹窗关闭重开恢复，并如实记录会话前提与未通过项，不以 CLI 成功或截图代替插件端到端验证。
